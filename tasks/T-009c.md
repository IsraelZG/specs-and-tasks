# T-009c · Auth browser-compat no canal de controle WS

## 0. Ambiente de Execução Obrigatório
- **Runtime:** Node.js v20+
- **Package Manager:** `pnpm` (NÃO USE npm ou yarn)

## 1. Objetivo
Adaptar o canal de controle WebSocket (`/control`) para funcionar em **browsers**. O `WebSocketControlClient` (T-009b, `ready`) usa o pacote `ws` do Node, que permite passar `Authorization: Bearer <token>` como header customizado no upgrade HTTP. A API nativa `new WebSocket(url)` do browser **não permite custom headers**. O Hub (`initControlRelay` em `controlRelay.ts`, T-010 `done`) só aceita `Authorization: Bearer` — precisa de uma segunda rota de auth compatível com browser.

> **Derivação:** Decisão D1 de T-009b §6 fixou Node-only para V0 e moveu browser-compat para follow-up. Esta task é esse follow-up. *(fonte: `tasks/T-009b.md` §6 D1)*

```ts
// --- packages/client-sdk/src/BrowserWebSocketControlClient.ts ---
import type { ControlPort, ControlEvent } from '@plataforma/core'; // T-009a (spec ready, código ainda não existe)

export interface BrowserAuthOptions {
  /** Token de sessão. Passado via query string `?token=<valor>` (único método compatível com browser WebSocket API sem custom headers). */
  token: string;
  /** URL do endpoint de controle, ex.: 'ws://localhost:8787/control' */
  url: string;
}

export class BrowserWebSocketControlClient {
  /**
   * @param url   URL do endpoint WS. O token é apensado como query string: `${url}?token=${token}`
   * @param token session token
   */
  constructor(url: string, token: string);

  /** Abre o WebSocket com auth via query string `?token=<token>`. Resolve no evento 'open'. Rejeita se o servidor fechar com 1008. */
  connect(): Promise<void>;

  /** Vincula o ControlPort local — mesmo padrão de T-009b. */
  bind(controlPort: ControlPort): void;

  close(): void;
}
```

**Wire format (derivado de `apps/system-peer/src/controlRelay.ts`:46-51 — código `done`):**
- Hub atual extrai token de `Authorization: Bearer <token>` no header do upgrade (`extractBearer`, linha 9-14).
- **Browser-compat adiciona:** o Hub também verifica `req.url` para `?token=<valor>` na query string, na função `extractToken(req)` (nova). Se ambos ausentes/vazios → fecha com 1008 `missing_session_token`.
- Token via query string tem precedência menor que Authorization header (se ambos presentes, Authorization vence).
- Demais wire: idêntico a T-009b (`{corr_id, cmd, payload}` no recebimento, `{corr_id, result}` na resposta).
