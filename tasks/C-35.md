# C-35 · Refactor: centralizar bytesToHex + utf8Encode/Decode em protocol/codec.ts

## 0. Ambiente de Execução Obrigatório
- **Runtime:** Node.js v20+
- **Package Manager:** `pnpm` (NÃO USE npm ou yarn)
- **Monorepo:** Turborepo (`pnpm build`, `pnpm test`, `pnpm lint` na raiz afetam todos os pacotes)

- **Capacidade-alvo:** haiku | sonnet | opus-spike *(ver regra "Dimensionamento de Tarefas" no CLAUDE.md)*

## 1. Objetivo
Eliminar 3 padrões de duplicação no monorepo, centralizando-os em `packages/protocol/src/codec.ts` (que já é a casa de `encode`/`decode`/`CodecError`):

1. **`bytesToHex(bytes: Uint8Array): string`** — hex lowercase, sem prefixo, sem separador. Substitui 4 cópias da mesma lógica (3 inline + 1 função local em `peerId.ts`).
2. **`utf8Encode(s: string): Uint8Array`** — wrapper canônico para `new TextEncoder().encode()`. Substitui ~16 sites inline + 6 sites com constante hoistada (`const encoder = new TextEncoder()`).
3. **`utf8Decode(bytes: Uint8Array): string`** — wrapper canônico para `new TextDecoder().decode()`. Substitui ~8 sites inline + 3 sites hoistados.

**Origem:** conversa com o humano após C-24/C-34, que mapeou "código com função praticamente idêntica espalhada em vários locais" como risco arquitetural (analogia ao bug BigInt que o C-34 consertou: a conversão estava replicada em 8 sites e o fix centralizou). Este C-35 fecha o mesmo padrão preventivo para 3 outras funções.

**Não-objetivo (explícito):** centralizar `sha256` (já há 3 cópias, mas constrained — `protocol ← crypto ← core ← transport`; `protocol` não pode importar de `crypto`, então as cópias em `protocol/rbsr/` são deliberadas). Centralizar `Date.now()`/`ClockPort` (já há abstração; usos restantes são fallbacks intencionais). Centralizar `JSON.parse(...) as Type` (cast é o ponto, wrapper só esconde). Centralizar `throw new Error(\`...\`)` (templates divergem).

### Casos enumerados para `codec.test.ts` (estender arquivo existente, 3 novos `describe`)

**`bytesToHex`** (6 casos):
1. `bytesToHex(new Uint8Array([]))` → `""` (vazio)
2. `bytesToHex(new Uint8Array([0]))` → `"00"` (1 byte zero → 2 chars)
3. `bytesToHex(new Uint8Array([0xFF]))` → `"ff"` (lowercase, sem prefixo `0x`)
4. `bytesToHex(new Uint8Array([0x0a, 0xff, 0x01]))` → `"0aff01"` (3 bytes, padding correto)
5. `bytesToHex(new Uint8Array(32).fill(0xab))` → string de 64 chars `"ab" * 32` (tamanho típico de hash)
6. round-trip `bytesToHex(x) === bytesToHex(x)` é identidade (mesmo input → mesmo output, óbvio; marcador para futuros erros)

**`utf8Encode`** (4 casos):
7. `utf8Encode("")` → `new Uint8Array(0)` (vazio)
8. `utf8Encode("hello")` → `new Uint8Array([104, 101, 108, 108, 111])` (ASCII puro)
9. `utf8Encode("ação")` → `new Uint8Array([0xc3, 0xa7, 0xc3, 0xa3, 0x6f])` (UTF-8 multibyte, ç/ã)
10. `utf8Encode("🎉")` → `Uint8Array` de 4 bytes (UTF-8 4-byte emoji: `0xf0 0x9f 0x8e 0x89`)

**`utf8Decode`** (3 casos + round-trip):
11. `utf8Decode(new Uint8Array(0))` → `""` (vazio)
12. `utf8Decode(new Uint8Array([104, 101, 108, 108, 111]))` → `"hello"`
13. `utf8Decode(new Uint8Array([0xc3, 0xa7, 0xc3, 0xa3, 0x6f]))` → `"ação"`
14. `utf8Decode(utf8Encode(s))` === `s` para `s` em `["", "hello", "ação", "🎉cafe", "device-sync-v1"]` (round-trip)

### Pegadinhas conhecidas *(armadilhas que derrubam um modelo leve)*
- **`peerId.ts:22`** tem sua própria `function bytesToHex(bytes: Uint8Array): string` (não inline) — removê-la requer adicionar `bytesToHex` ao import. Esquecer o import deixa o arquivo quebrado.
- **`lineage.ts:179-183`** também tem função local `bytesToHex` (a busca por `byte.toString(16).padStart` retorna hits tanto em funções nomeadas quanto em loops inline — contar com cuidado).
- **Constantes hoistadas** (`const encoder = new TextEncoder()`) — o helper `utf8Encode` mantém uma instância única internamente (mais perf-friendly que criar uma por chamada). Quem remove a constante deve remover TODAS as chamadas que a usavam, não só a constante.
- **`noiseHandshake.ts:52`** tem `const utf8 = (s) => new TextEncoder().encode(s)` — esse é o shadowing que queremos eliminar. Substituir TODAS as chamadas a `utf8(...)` nessa arquivo pelo import `utf8Encode` do `protocol/codec`.
- **`TextEncoder`/`TextDecoder` são stateful no Node < 11 / browser antigos** — mas o codebase exige Node 20+ e target browser moderno, então stateful não é preocupação. A instância hoisted em `_encoder`/`_decoder` é safe para reuso.
- **`bytesToHex` deve ser `lowercase`** (não uppercase) — `peerId.ts` já produz lowercase, é o padrão da casa (consistente com `bytesToHex` em `core/coverage/src/lineage.ts.html`).
- **Não usar `Number.prototype.toString(16)` para o byte** — não funciona para bytes únicos (e.g., `15..toString(16)` → `"f"`, sem padding). O `byte.toString(16).padStart(2, '0')` é a forma idiomática.
